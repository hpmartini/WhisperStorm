# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WhisperStorm is a native macOS menu-bar app for system-wide dictation (a local WisprFlow clone). A global hotkey records the microphone, transcribes **entirely on-device** (WhisperKit/CoreML, or an OpenAI-compatible local HTTP server), and pastes the result into the focused app. No cloud calls. macOS 14+, Apple Silicon, Swift/SwiftUI.

`PROMPT.md` is the original German build spec (the source of truth for product intent and non-goals); `README.md` is the user-facing guide; `TASK.md` is a chronological issue log documenting past bugs and their root causes — read it before touching insertion or signing.

## Build & run

The project has **no Xcode project checked in** — `WhisperStorm.xcodeproj/` is generated by XcodeGen from `project.yml` and gitignored. Never edit the `.xcodeproj`; change `project.yml` and regenerate. There is no test target.

```bash
# Once per machine — stable signing identity so the Accessibility grant survives rebuilds:
./scripts/setup-signing.sh

# Build & run (repeatable):
xcodegen generate && xcodebuild -project WhisperStorm.xcodeproj -scheme WhisperStorm -configuration Release -derivedDataPath build build && open build/Build/Products/Release/WhisperStorm.app
```

Requires `brew install xcodegen`. After editing `project.yml` (targets, packages, entitlements, Info.plist), you must re-run `xcodegen generate` before building. Runtime logs go to the unified log (`os.Logger`, subsystem in `Sources/Support/Log.swift`) **and** a plain file at `~/Library/Logs/WhisperStorm.log` (insertion diagnostics — the unified log proved unreadable, see `TASK.md`).

## Architecture

`DictationCoordinator` (`Sources/App/`) is the central `@MainActor` orchestrator and the entry point for understanding the app — it wires hotkey → audio capture → transcription → text insertion, and owns the shared singletons (`AppSettings.shared`, `AppState`, `AudioLevelStore`, device/model managers). The full dictation flow lives in its `startDictation` / `stopDictation` / `runTranscription` methods. A new trigger for recording (e.g. an API, a menu action) hooks in here, not in the audio or transcription layers.

`WhisperStormApp.swift` is `@main`: a `MenuBarExtra` scene (no Dock icon — `LSUIElement: true`) plus a `Settings` scene, both injecting `coordinator` and its sub-objects as environment objects. `AppDelegate` handles launch-time onboarding/permission checks.

**Transcription is a swappable protocol.** `TranscriptionProvider` (16 kHz mono Float32 PCM in, text out) has two implementations selected via `AppSettings.providerKind`:
- `WhisperKitProvider` — an `actor` that caches the loaded CoreML pipeline and reloads only when the model variant changes.
- `OpenAICompatibleProvider` — POSTs WAV (via `WAVEncoder`) to `<baseURL>/v1/audio/transcriptions`. Any OpenAI-compatible STT server works (e.g. a `speaches`/faster-whisper Docker container).

`prepare()` is split from `transcribe()` specifically so the coordinator can show a "Preparing model…" state during the expensive one-time CoreML load — do not fold expensive setup back into `transcribe()`.

**Audio** (`Sources/Audio/`): `AudioCaptureEngine` taps `AVAudioEngine`, downsamples to 16 kHz mono via `AVAudioConverter` on the tap thread, and pushes smoothed RMS levels into `AudioLevelStore`. `AudioLevelStore` is deliberately **not** `@Published` (buffer-rate updates would cause a SwiftUI invalidation storm); the 60 fps waveform overlay polls it via `TimelineView` instead.

State flows one way: the coordinator mutates `AppState.phase` (`idle`/`recording`/`transcribing`/`success`/`error`), and the menu bar icon + overlay observe it.

## macOS-specific constraints (read before changing insertion, signing, or entitlements)

These are non-obvious and have already caused bugs (see `TASK.md`):

- **Not sandboxed** (`ENABLE_APP_SANDBOX: NO`). `CGEvent` posting and `AXIsProcessTrusted()` do not work in a sandbox. Do not add the App Sandbox.
- **Signature stability is load-bearing.** macOS TCC binds the Accessibility grant to the app's code signature. `project.yml` signs with a stable self-signed identity (`WhisperStorm Dev`) created by `scripts/setup-signing.sh` for exactly this reason. If that identity is missing, codesign falls back to ad-hoc, the cdhash changes every build, and text insertion silently breaks (transcript reaches only the clipboard). After the first signed build the user must grant Accessibility once; it then persists.
- **Insertion is best-effort with a clipboard fallback.** `TextInserter.insert` always writes the clipboard first (no restore of prior contents — by design), then tries to paste by synthesizing Cmd+V via `CGEvent`. It returns a `clipboardOnly` outcome (surfaced as a notification) when Accessibility is untrusted, Secure Keyboard Entry is active, or nothing is focused. macOS **silently drops** synthetic keystrokes from untrusted processes — there is no error, so never assume a posted event succeeded.
- **The overlay must never steal focus.** It is a non-activating floating `NSPanel`; keep it that way or paste-into-focused-app breaks.

## Conventions

- Code, comments, identifiers, and UI strings are **English**. Transcription itself must handle German and English (auto-detect or fixed via `TranscriptionLanguage`).
- `@MainActor` on UI/state/settings; the WhisperKit pipeline is an `actor`; audio buffer processing runs off-main on the tap thread with an `NSLock`-guarded sample buffer. `SWIFT_STRICT_CONCURRENCY: minimal` in `project.yml`.
- Settings persist through `AppSettings` (UserDefaults-backed `@Published` properties with `didSet`). WhisperKit models live in `~/Library/Application Support/WhisperStorm/models`; `WhisperModelManager` owns download/presence/removal and the curated model list.
- Errors never fail silently: surface them in the overlay (`AppState.phase = .error`) **and** as a user notification (`NotificationManager`).
